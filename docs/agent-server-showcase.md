# Agent 수집과 서버 진단 표시

React 진단 첫 화면(`app/page.tsx`)에서 Windows Agent의 수집 항목과 진단 서버의
역할을 안내한다. `Agent로 내 PC 진단` 버튼은 기존 `/api/scans/start`를 사용한다.

## 실제 상태와 진행 단계

`app/scan-journey.ts`가 기존 스캔 상태를 다음 다섯 단계로 변환한다.

| 단계 | 진행 중으로 표시하는 근거 |
| --- | --- |
| 권한 승인 | Agent 실행 상태의 `phase=permission` |
| PC 정보 수집 | `phase=collecting` |
| 로컬 저장 | `phase=saving` |
| 서버 전송 | `phase=uploading` |
| 진단 결과 | 수집·전송 완료 후 해당 스캔의 진단 API 응답 및 현재 실행 확인을 기다리는 동안 |

Agent의 백분율은 **수집·전송 진행률**이다. 서버 분석 진행률은 API가 제공하지
않으므로 임의의 백분율을 만들지 않는다. `/api/scans/{scanId}` 요청과 실행 상태
확인이 끝나고 화면의 결과 ID가 완료된 실행의 ID와 일치해야 마지막 단계가 완료된다.
결과가 캐시에 있으면 별도 분석을 하지 않고 바로 반환할 수도 있다.

연결 끊김·상태 재확인 중에는 단계를 미확인으로 표시한다. 수집 실패 응답은 실패한
원래 단계를 보존하지 않으므로 앞선 단계들을 임의로 완료 처리하지 않는다.
결과 조회만 실패했다면 이미 확인된 수집·전송 완료는 유지하고 마지막 단계에 조회
실패를 표시한다. 결과 재시도는 Agent를 새로 실행하지 않는다.

## 수집과 진단 기록

- 수집 시각은 `sources[].collectedAt`, 진단 생성 시각은 `generatedAt`를 사용한다.
  수집 시각이 없으면 진단 생성 시각으로 대체하지 않는다.
- 출처별 수집 상태와 Agent 버전을 표시한다. WMI와 CIM은 같은 하드웨어 수집기의
  출처이므로 완료 개수는 수집기 수가 아닌 **출처 수**다.
- 펼침 영역은 서버가 반환한 진단 항목별 `evidence`와 규칙 코드, 스캔 ID를 표시한다.
- 새 스캔 중에는 기존 결과를 이전 스캔 기록으로 구분한다. 예시 데이터는 예시로
  표시하며 실제 실행의 진행 완료 근거로 사용하지 않는다.

검증: `npm run test:ui`, `node node_modules/typescript/bin/tsc --noEmit`,
`npm run build`. 별도 합성 응답을 사용한 브라우저 검증으로 단계 전환, 연결 복구,
결과 지연·조회 실패·재시도, 수집 기록, 320px/390px 배치를 확인했다.
