# 스캔 진행 상태 복구

## 계획

화면의 버튼 클릭에 종속된 대기 루프를 서버 상태 감시로 바꾼다. 서버가 살아 있는
동안 페이지 새로고침, 새 탭, 네트워크 재접속에서 기존 스캔을 이어받는다.

## 구현

- 화면 진입 시 `/api/scans/status`를 확인하고 이후 1.5초 간격으로 감시한다.
  상태 요청 제한 시간은 5초이며 요청은 순차 실행한다.
- 상태를 처음 확인하거나 연결을 복구하는 동안 시작 버튼을 잠가 중복 시작을 막는다.
- 실행 중이면 서버의 진행률과 수집 항목을 표시한다. 브라우저가 자체적으로 스캔을
  다시 시작하거나 5분 경과를 이유로 서버 작업을 실패 처리하지 않는다.
- 완료 시 저장된 최신 진단 결과를 불러온다. 실패 시 서버 메시지를 보여준다.
  같은 실행의 완료 처리는 한 번만 수행하고 다음 실행도 감지한다.
- 상태 조회나 완료 결과 조회 실패 시 감시를 계속한다. 연결 복구 후 진단 데이터도
  다시 불러오며, 이전에 표시한 진단은 연결이 끊겨도 보존한다.
- 완료 결과 로딩 중에는 새 스캔을 막는다. 화면 이탈 시 감시 타이머를 종료하고
  진행 중인 요청의 늦은 응답을 화면에 반영하지 않는다.
- 예시 화면에서 실제 스캔을 시작하면 서버 상태 감시로 전환한다.

서버 자체가 재시작하면 현재 메모리에 있는 실행 정보는 복구되지 않는다.
실행 상태의 디스크 저장과 재시작 후 작업 복구는 후속 안정화 작업이다.
현재 최신 결과 조회 경로는 유지하며 실행별 정확한 결과 연결은 다음 작업에서 보강한다.

## 검증

`npm run test:ui`는 새 화면의 실행 이어받기, 연결 실패 후 복구, 완료 중복 처리 방지,
다음 실행 감지, 완료 결과 로딩 재시도, 화면 이탈 후 응답 무시를 검증한다.
프런트엔드 production build와 TypeScript 검사도 수행한다.
