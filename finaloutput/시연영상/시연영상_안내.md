## 촬영 범위와 해석

실측은 2026-11-10에 Windows Agent CLI를 비관리자 권한으로 실행하여 hardware, performance, storage_health, reliability를 수집하고, 전용 로컬 서버로 전송했다. UAC 승인 화면과 실제 스캔 진행 화면은 녹화하지 않았다. 영상의 첫 두 장면은 웹 버튼과 처리 흐름을 설명하며, 수집 완료를 나타내는 진행 상태를 만들어 넣지 않았다.

구매 분기는 저장소의 `demo/recommendation-snapshot.json`을 사용했다. 측정값은 그대로 두고 이번 실행의 ID·시각만 부여하여 서버에 입력했다. 원래 문서에 제시된 ‘끊김 → 진단 → 근거 → 호환 후보 → 구매처’ 시나리오를 보여주기 위한 데이터이며 현재 PC의 이상 상태나 실측 판매가가 아니다. 상단에 실측/예시를 계속 표시했다.

로컬 Gemma는 사용하지 않았다. 화면의 설명은 규칙 기반 안내다. 미확인 가격·재고·장착 조건과 프로그램의 미확인 값은 숨기거나 임의의 값으로 바꾸지 않았다. 교체 효과는 성능 향상률을 실측한 결과가 아니다.

화면 이동과 클릭을 실제 브라우저에서 녹화했다. 설명용 포인터를 추가했으며, 메모리 근거 장면은 글씨를 읽기 쉽게 해당 카드 영역을 확대했다. 다른 후보를 비교하는 별도 촬영에서는 카드 전체를 화면에 배치하기 위해 촬영 브라우저에만 하단 스크롤 여백을 추가했다. 프로젝트 제품 소스는 수정하지 않았다.

## 검수와 편집 원본

전체 MP4 디코딩 오류 0건, 2700프레임·90.000초·1920×1080 확인. 모든 장면의 인코딩된 대표 프레임과 자막 배치를 확인했다. 프레임 검수와 전체 디코딩을 수행했으며, 사람이 전체 영상을 연속 재생하여 검수한 기록은 아니다.

재편집 소스와 원본 녹화: `outputs/videos/20261110/`. 주요 파일은 `capture.cjs`, `capture-manifest.json`, `render_video.py`, `timeline.json`, `verification.json`이다. 실제 PC의 원시 수집 자료는 `.speccheck/video-20261110/`에 별도로 보관했으며 납품 폴더에 포함하지 않았다.

재촬영할 때에는 전용 Backend 8011번과 UI 3011번을 실행한 후 다음 순서로 실행한다. 다른 서버나 기존 수집 DB를 사용하지 않는다.

```powershell
# SpecCheck 루트에서, 전용 서버가 실행 중인 상태
.venv\Scripts\python.exe -X utf8 outputs\videos\20261110\prepare.py
node outputs\videos\20261110\capture.cjs all
node outputs\videos\20261110\capture.cjs detail
.venv\Scripts\python.exe -X utf8 outputs\videos\20261110\render_video.py
```

현재 촬영 원본으로 다시 렌더링할 경우 `render/` 내 이미 생성된 장면 파일을 재사용한다. 완전히 새로 촬영할 때는 기존 프로젝트 폴더를 보존하고 새 날짜의 작업 폴더를 사용한다. Python Pillow, FFmpeg/ffprobe, 기존 Playwright와 Microsoft Edge가 필요하다.
